# 4. הפתרון והמיצוב

## הפתרון במשפט

שכבת תכנון והחלטה שמרכזת את מקורות הסמסטר, בוחרת משימה אחת, בונה תוכנית לפי זמן פנוי אמיתי, ומסבירה למה.

## עקרונות

1. **פחות זה יותר.** מסך "היום" מציג משימה אחת והתוכנית להיום. כל דבר חדש נכנס מקופל או בדף הקורס.
2. **הסבר לכל החלטה.** שורה אחת: "10 ימים, כ-10 שעות עבודה, להתחיל היום".
3. **המודל מחלץ, הקוד מחליט.** מייל מתפרש למבנה, וכללים קבועים קובעים מה קורה. אי-ודאות הולכת לאישור.
4. **פונקציית תעדוף אחת.** רק `buildPlan` קובעת סדר. אין לוגיקת תעדוף נוספת בשום מקום.
5. **עובד גם בלי שרת.** הענן והאוטומציות הם תוספת.
6. **פרטיות כברירת מחדל.** נתונים אישיים לא בריפו, סודות רק בהגדרות מקומיות, בלי סיסמאות.
7. **תכונה חדשה נכנסת כבויה.** מופעלת רק אחרי בדיקה.

## איך המענה עובד

```
מקורות                 עיבוד                      תוצאה
מודל (iCal)      ->    סנכרון, התאמה לקורס  ->   מועדים
מיילים (IMAP)    ->    חילוץ + כללים         ->   שינויי מערכת / אישור
יומן Google      ->    זמן תפוס (A)          ->   שעות פנויות אמיתיות
נתוני הקורסים    ->    מפגשים, משקלות        ->   קצב וציונים
                              |
                         buildPlan
                              |
                  משימה אחת + תוכנית להיום + הסבר
```

## מה בפנים ומה בחוץ

| בפנים | בחוץ, ולמה |
| --- | --- |
| תוכנית יומית ומשימה אחת | סיכומי הרצאות וכרטיסיות: מתחרים חזקים, דורש צוות |
| מעקב קצב והשלמות | משרות, מלגות וקורות חיים: לא קשור לשאלה |
| ציונים וציון נדרש | חיבור ישיר לפורטל האוניברסיטה: פגיעה בפרטיות ותלות בהסכמה |
| אוטומציות מודל ומייל | הפצה ושיווק עכשיו: המטרה היא תיק עבודות |
| קריאה ושיבוץ ביומן | שליחת מיילים בשמך: הכלי לעולם לא שולח |

## ארכיטקטורה

הפירוט המלא: [ARCHITECTURE.md](../ARCHITECTURE.md). בקצרה:

- `js/logic.js` טהור, בלי DOM ובלי רשת. משותף לדפדפן ולאוטומציות.
- `js/app.js` ממשק, שמירה מקומית וסנכרון לענן.
- Supabase: חמש טבלאות עם הרשאות לפי `auth.uid()`.
- אוטומציות: workflows שנוצרים מקוד, ורצים ב-Actions.

### שינויים נדרשים בארכיטקטורה לפי השלבים

| שלב | שינוי |
| --- | --- |
| C | סקריפט שקורא IMAP ומשתמש ב-`automations/lib/email.js`. workflow המיילים מבוסס טריגר של n8n ולכן לא רץ ב-`run-local.js` |

| B | טבלת `block_events` שמקשרת בלוק לאירוע ביומן. כתיבה רק ליומן ייעודי |
| ניטור | שדה "סנכרון אחרון" באפליקציה, והתראה על ריצה שנכשלה |

## כללי הבטיחות

- אסור לשנות או למחוק אירוע ביומן שהכלי לא יצר.
- בלוק מקובע לא זז כשהתוכנית נבנית מחדש.
- אם הסנכרון נכשל לאורך זמן, מציגים זאת ולא כותבים ליומן.
- נתוני הסמסטר האמיתיים, גיבויים וסודות לא עולים לריפו הציבורי.
- לא נכנסים ל-scopes של Gmail: הם מסווגים "מוגבלים" ודורשים הערכת אבטחה שנתית. IMAP לא דורש scope בכלל.
- סיווג ה-scopes משתנה. בודקים מול התיעוד של Google בזמן המימוש.
