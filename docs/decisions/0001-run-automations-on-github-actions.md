# 0001 – הרצת האוטומציות ב-GitHub Actions

סטטוס: אושר

## הקשר
האוטומציות (סנכרון Moodle, תדריך בוקר, תזכורות) רצות על n8n במחשב האישי, ורק כשהוא דולק. ריצה שהוחמצה לא מתבצעת מחדש. זה חושף את הכלי לפער שקט: מי שמסתמכת עליו לא יודעת שהסנכרון לא רץ.

## אפשרויות
| אפשרות | יתרון | חיסרון |
| --- | --- | --- |
| להישאר על המחשב | בלי שינוי ובלי עלות | תלוי במחשב דולק |
| GitHub Actions עם `cron` | חינם, גלוי בריפו, לא תלוי במחשב, קוד האוטומציות נשאר | תזמון יכול להתעכב בכמה דקות, והסודות עוברים ל-GitHub Secrets |
| פונקציות Supabase | ליד הנתונים, מתאים למשתמשות רבות | כתיבה מחדש גדולה יותר |
| n8n בענן | אותם workflows | עלות חודשית |

## החלטה
GitHub Actions, שמריץ את `automations/run-local.js`. הסיבות: ללא עלות, שומר את הקוד והבדיקות הקיימים, ומוסיף תהליך שאפשר להראות בריפו הציבורי.

## תוצאות
- `run-local.js` צריך לקרוא סודות גם ממשתני סביבה, ולא רק מ-`automations/.env`.
- workflow המיילים משתמש בטריגר IMAP של n8n, ולכן דורש סקריפט נפרד.
- נדרשת התראה כשריצה נכשלת, כדי לא לחזור לפער השקט.
- אם הכלי יופץ למשתמשות נוספות, ההחלטה תיבחן מחדש מול פונקציות Supabase.
