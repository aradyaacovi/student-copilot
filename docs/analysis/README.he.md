# ניתוח נתונים

התיקייה הזאת מחזיקה את נתוני הסמסטר כטבלאות שטוחות, לניתוח בכלים חיצוניים. הקבצים נוצרים בפקודה אחת:

```powershell
npm run export
```

הפקודה קוראת את נתוני ההדגמה בלבד, ולכן אין בתיקייה הזאת שום נתון אישי. השעון מקובע לתאריך של צילומי התיעוד, כדי שהרצה חוזרת לא תשנה את הקבצים רק כי התאריך התקדם. השורות נבנות ב-`js/logic.js`, אותו מודול שמחשב את מעקב הקצב באפליקציה, ולכן מספר המפגשים בקובץ זהה למה שמוצג על המסך.

## הטבלאות

| קובץ | שורה אחת היא | למה היא טובה |
| --- | --- | --- |
| `sessions.csv` | מפגש אחד שהתקיים או שעתיד להתקיים | עומס שעות לפי יום, לפי שבוע ולפי קורס, ופיגור בצפייה |
| `deadlines.csv` | מטלה או מועד עם תאריך | פיזור ההגשות על פני הסמסטר ומשקלן בציון |
| `grade-components.csv` | רכיב ציון אחד בקורס | מה מרכיב את הציון ואיפה מרוכז המשקל |

## העמודות החשובות

- `status`: האם המפגש התקיים או שהוא עתידי. ספירת שעות עבר ושעות עתיד נעשית בעמודה הזאת.
- `watched`: האם ההרצאה נצפתה. ריק במפגש עתידי. במצב הדגמה הערך מגיע מנתוני ההדגמה, ואצל סטודנטית אמיתית הסימון נשמר בדפדפן ולא מיוצא.
- `makeup`: מפגש השלמה, כלומר כזה שלא נמצא בלו״ז הקבוע.
- `semester_week`: שבוע הסמסטר, החל מ-1. העמודה הזאת היא הציר הנוח ביותר לטבלת ציר.
- `hours`: אורך המפגש בשעות עשרוניות, כדי שאפשר יהיה לסכם אותן.

שיעור שבוטל ויום בלי לימודים אינם מופיעים בקובץ כלל, בהתאם לכלל של הפרויקט: שיעור שבוטל נמחק מהלו״ז ולא מסומן.

## פתיחה באקסל

הקבצים נכתבים בקידוד שאקסל מזהה, ולכן העברית נפתחת נכון בלחיצה כפולה. אם העמודות נדחסות לעמודה אחת, סימן שהופעל ייבוא עם מפריד אחר: לייבא דרך לשונית הנתונים, ולבחור פסיק כמפריד.
